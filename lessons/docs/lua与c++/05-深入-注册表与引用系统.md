# 05 · 注册表与引用系统

> 注册表是 Lua VM 的"保险柜"——C 端存数据、防 GC、跨函数共享的秘密武器。

---

## 5.1 注册表是什么？

### 类比理解

```
全局表 _G：
  Lua 端可见，存 print、math、你的全局变量
  任何 Lua 代码都能读写

注册表 LUA_REGISTRYINDEX：
  C 端专用，Lua 代码看不到
  你可以在里面存任何东西，Lua 脚本永远访问不到
```

### 访问方式

```c
// 注册表不是一个"拿到指针"的 table，而是通过虚拟索引访问:
lua_pushstring(L, "myKey");              // key
lua_pushnumber(L, 42);                   // value
lua_settable(L, LUA_REGISTRYINDEX);      // registry["myKey"] = 42

// 读取:
lua_pushstring(L, "myKey");
lua_gettable(L, LUA_REGISTRYINDEX);      // 取出 registry["myKey"] → 42
int val = lua_tointeger(L, -1);
lua_pop(L, 1);
```

**伪索引 `LUA_REGISTRYINDEX`**：不是真实的栈位置，而是告诉 Lua VM "操作注册表"的特殊标记。

```
注册表内容:

│ ...                              │
└─────────────────────────────────┘
```

## 5.3 `luaL_ref` —— 注册表引用系统

### 问题：怎么在 C 端保存 Lua 值的引用？

```c
// ❌ 不能这样保存:
lua_State *L = ...;
lua_newtable(L);           // 栈上有一个 table
// 等一下！我需要把这个 table 存起来，下次用...
// 但 lua_newtable 返回 void！没有"句柄"可以存！

// ✅ 使用 luaL_ref:
lua_newtable(L);                           // 栈: [table]
int ref = luaL_ref(L, LUA_REGISTRYINDEX);  // table 从栈移到注册表，返回整数引用
// ref 是一个整数（如 3），可以存到 C++ 变量里
```

### luaL_ref 做了什么？

```
调用前:                      调用后:
栈: [..., table]             栈: [...]（table 被移走）
                             注册表:
                               [ref_3] = table  ← 这个 table 现在安全了
                               
ref = 3（返回的整数引用）

luaL_ref 自动分配一个不重复的整数作为 key
```

### 取出：`lua_rawgeti`

```c
int ref = 3;  // 之前存的引用
lua_rawgeti(L, LUA_REGISTRYINDEX, ref);  
// 效果: 把注册表中 [ref_3] 的值压到栈顶
// 栈: [..., table_back]

// 使用 table...
// 用完后
lua_pop(L, 1);
```

### 释放：`luaL_unref`

```c
luaL_unref(L, LUA_REGISTRYINDEX, ref);
// 效果: 注册表中 [ref_3] = nil
// 如果 table 没有其他引用，Lua GC 会回收它
```

## 5.4 项目中的四个引用场景

### 场景 1：保存沙盒 table（envRef）

```c
// initEntity() 中:
int outEnvRef;
lua_newtable(L);                           // 创建沙盒
// ... 设置元表、注入 API ...
outEnvRef = luaL_ref(L, LUA_REGISTRYINDEX); // 存入注册表

// ScriptSystem::Impl 中保存:
std::map<flecs::entity_t, int> envRefs;     // 实体 ID → 注册表引用
envRefs[entity_42] = outEnvRef;             // 以后通过 entity ID 找回沙盒

// 使用时:
int ref = envRefs[entity_42];
lua_rawgeti(L, LUA_REGISTRYINDEX, ref);     // 取出沙盒 table
```

### 场景 2：保存编译后的函数（funcRef）

```c
// compileAndLoad() 中:
luaL_loadstring(L, src.c_str());               // 编译脚本 → 函数在栈顶
*outRef = luaL_ref(L, LUA_REGISTRYINDEX);      // 存入注册表

// 后续使用:
lua_rawgeti(L, LUA_REGISTRYINDEX, funcRef);    // 取出函数
// 执行或做其他操作...
```

### 场景 3：保存信号回调函数

```c
// api_connect() 中:
lua_pushvalue(L, 2);                           // 复制回调函数
int ref = luaL_ref(L, LUA_REGISTRYINDEX);      // 存入注册表

// 创建 SignalConnection:
SignalConnection conn{entityId, "c" + std::to_string(ref)};
//                                 ↑
//                    "c3" → 通过这个名字在全局表找到函数

// 取出:
lua_rawgeti(L, LUA_REGISTRYINDEX, ref);        // 取出函数
lua_setglobal(L, "c3");                        // 同时存到全局表（让 Lua 代码也能访问）
```

### 场景 4：`__active_ctx`（不用 ref，用字符串 key）

```c
// 不是 luaL_ref，是直接用字符串 key 读写:
lua_pushstring(L, "__active_ctx");
lua_pushlightuserdata(L, &ctx);
lua_settable(L, LUA_REGISTRYINDEX);

// 读取:
lua_pushstring(L, "__active_ctx");
lua_gettable(L, LUA_REGISTRYINDEX);
```

## 5.5 为什么信号回调要同时存注册表和全局表？

```
注册表:                           全局表 _G:
  [ref_3] = function(hp) ...       c3 = function(hp) ...
  [ref_7] = function(dmg) ...      c7 = function(dmg) ...

  用途: C 端管理生命周期           用途: emit 时通过 callbackName
  (luaL_ref/luaL_unref)            (如 "c3") 找到函数执行
```

**双重存储的原因**：

- **注册表**（通过 ref）：C 端引用计数，防止函数被 GC 回收
- **全局表**（通过 "c3" 名字）：emit 时 `lua_getglobal(L, "c3")` 快速取出执行

如果只存全局表 → Lua GC 可能在没人引用时回收
如果只存注册表 → emit 时需要用 `lua_rawgeti` 加 ref 编号，不够语义化

## 5.6 编译缓存也用到了类似思想

```c
struct CachedChunk {
    std::string data;    // 编译后的字节码（lua_dump 产出）
    time_t mtime = 0;    // 源文件修改时间
};

static std::map<std::string, CachedChunk> g_compiledChunks;
```

虽然没有直接用 `luaL_ref`，但原理类似：

- 编译脚本 → `lua_dump` 导出字节码到 C++ 内存 → 缓存起来
- 后续帧直接 `luaL_loadbuffer` 加载字节码（跳过编译阶段）

---

## 5.7 总结

```
注册表三大用途:

  ① 存 C 端私密数据（__active_ctx）
     Lua 代码看不到，只有 C 函数能访问

  ② luaL_ref 引用系统
     让 C 端能"持有" Lua 值的引用，防止 GC 回收
     返回整数 ref，可存到 C++ 变量中

  ③ 跨函数共享
     不同 C 函数调用之间，通过注册表传递数据
     （本项目的 __active_ctx 就是典型例子）
```
