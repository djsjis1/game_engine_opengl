# 06 · 信号系统设计 —— Godot 风格 connect/emit

> 如何在 ECS 架构中用 Lua 实现实体间的事件通信。

---

## 6.1 需求场景

```
场景：玩家子弹击中敌人

实体 A (子弹)                    实体 B (敌人)
─────────────                   ─────────────
碰撞检测发现"击中"             需要执行扣血逻辑
emit("hit", 50)  ───────────→  on_hit(50) 被调用
                               hp = hp - 50
                               if hp <= 0: emit("died")
```

**核心需求**：

- 实体 A 不知道谁会监听它的信号（解耦）
- 实体 B 可以被删除，A 不应该引用已删除的 B（安全）
- Lua 脚本中使用，语法简洁

---

## 6.2 数据模型

```
SignalConnection:               SignalComponent:
┌─────────────────┐            ┌──────────────────────────────┐
│ listenerId      │            │ signalMap:                   │
│ callbackName    │            │   "hit" → [                  │
└─────────────────┘            │     {B, "c3"},              │
                               │     {C, "c7"}               │
                               │   ]                          │
                               │                              │
                               │ listensTo:                   │
                               │   A的ID → ["hit", "healed"]  │
                               └──────────────────────────────┘
```

### signalMap —— 正向：我发信号时通知谁

```
emit("hit", 50)
  → 查 signalMap["hit"]
    → [{listenerId: B, callbackName: "c3"}, {listenerId: C, callbackName: "c7"}]
    → 调 _G["c3"](50)  ← 实体 B 的回调
    → 调 _G["c7"](50)  ← 实体 C 的回调
```

### listensTo —— 反向：我删掉时清理正向引用

```
实体 B 被销毁
  → 查 B 的 listensTo
    → {A的ID → ["hit", "healed"], ...}
    → 去 A 的 signalMap["hit"] 里删掉 {B, "c3"}
    → 去 A 的 signalMap["healed"] 里删掉 {B, ...}
```

**如果没有反向索引**：B 删除后，A 的 signalMap 里还留着 `{B, "c3"}`，A 再次 emit("hit") 时尝试调用一个已删除实体的回调 → 悬垂引用。

## 6.3 回调函数的生命周期管理

```
api_connect("hit", function(dmg) ... end)

  步骤 1: luaL_ref → 获取整数引用 ref = 3
  步骤 2: 存为全局变量 _G["c3"] = function ...
  步骤 3: 创建 SignalConnection{listenerId=42, callbackName="c3"}

  为什么存两份？
  ┌─────────────────┐     ┌─────────────────┐
  │  注册表 [ref_3]  │     │  _G["c3"]       │
  │  = function ...  │     │  = function ... │
  │                  │     │                 │
  │  用途:           │     │  用途:          │
  │  防止 GC 回收    │     │  emit 时快速取出 │
  │  (C 端持有引用)  │     │  (名字语义化)   │
  └─────────────────┘     └─────────────────┘
```

## 6.4 connect / emit / connect_to 实现

### connect：我监听自己的信号

```c
static int api_connect(lua_State *L) {
    auto *c = getCtx(L);
    const char *name = luaL_checkstring(L, 1);  // "hit"
    luaL_checktype(L, 2, LUA_TFUNCTION);        // 回调函数

    auto *sig = getOrAddSignal(c);  // 确保有 SignalComponent

    // ① 存回调到注册表
    lua_pushvalue(L, 2);
    int ref = luaL_ref(L, LUA_REGISTRYINDEX);

    // ② 存回调到全局表
    SignalConnection conn{c->id, "c" + std::to_string(ref)};
    lua_rawgeti(L, LUA_REGISTRYINDEX, ref);
    lua_setglobal(L, conn.callbackName.c_str());  // _G["c3"] = function

    // ③ 写入 signalMap
    sig->signalMap[name].push_back(conn);

    return 0;
}
```

### emit：发出信号

```c
static int api_emit(lua_State *L) {
    auto *c = getCtx(L);
    const char *name = luaL_checkstring(L, 1);  // "hit"
    int nargs = lua_gettop(L) - 1;              // 参数个数（不含信号名）

    auto *sig = getOrAddSignal(c);
    auto it = sig->signalMap.find(name);
    if (it == sig->signalMap.end()) return 0;    // 没人监听

    for (auto &conn : it->second) {
        lua_getglobal(L, conn.callbackName.c_str());  // 取 _G["c3"]
        if (!lua_isfunction(L, -1)) { lua_pop(L, 1); continue; }

        // 把 emit 的参数复制给回调
        for (int i = 0; i < nargs; ++i)
            lua_pushvalue(L, i + 2);  // i+2 跳过信号名和函数自身

        // 调用
        if (lua_pcall(L, nargs, 0, 0) != LUA_OK) {
            fprintf(stderr, "[Lua] emit error: %s\n", lua_tostring(L, -1));
            lua_pop(L, 1);
        }
    }
    return 0;
}
```

### connect_to：跨实体监听

```c
static int api_connectTo(lua_State *L) {
    auto *c = getCtx(L);
    auto tid = (flecs::entity_t)luaL_checkinteger(L, 1);  // 目标实体 ID
    const char *name = luaL_checkstring(L, 2);            // 信号名
    luaL_checktype(L, 3, LUA_TFUNCTION);

    // ① 获取目标实体 B 的 SignalComponent
    auto *sig = getSignalMut(c->w, tid);  // 简化版

    // ② 在 B 的 signalMap 中注册回调（同 connect）
    int ref = ...;
    sig->signalMap[name].push_back({c->id, "c" + std::to_string(ref)});

    // ③ ★ 关键：在我的 listensTo 中记录反向引用
    auto *mySig = getOrAddSignal(c);
    mySig->listensTo[tid].push_back(name);
    //                ↑
    //  "我监听了实体 tid 的 name 信号"
    //  我删除时，根据这条记录去清理 B 的 signalMap
}
```

## 6.5 调用示意

```
               实体 A                         实体 B
          ┌────────────┐                ┌────────────┐
          │ SignalComp │                │ SignalComp │
          │ signalMap: │                │ signalMap: (空)
          │   "hit"→[] │                │            │
          │ listensTo: │                │ listensTo: │
          │   (空)     │                │  A→["hit"] │
          └────────────┘                └────────────┘

B 的脚本:
  self:connect_to(A_id, "hit", function(dmg)  ← ① 写 B.listensTo[A] + A.signalMap["hit"]
      self.hp = self.hp - dmg
  end)

A 的脚本:
  self:emit("hit", 50)  ← ② 查 A.signalMap["hit"] → 调 B 的回调
                              B 的回调中 self.hp = self.hp - 50
```

## 6.6 注意事项

### 回调函数可能已被 GC

```c
lua_getglobal(L, conn.callbackName.c_str());
if (!lua_isfunction(L, -1)) {
    lua_pop(L, 1);
    continue;  // ← 跳过已失效的回调
}
```

### 一个实体可以被 connect 多次

```lua
self:connect("hit", function(dmg) print("ouch1", dmg) end)
self:connect("hit", function(dmg) print("ouch2", dmg) end)
-- emit("hit", 50) 会触发两个回调！
```

### 参数透传

```lua
self:emit("hit", 50)
self:emit("hit", 50, "fire", {x=1, y=2})
-- 参数 2+ 都会被原样传给回调
```

## 6.7 总结

```
信号系统核心:

  signalMap:  我发出信号 → 通知谁？
  listensTo:  我监听谁 → 我删了要清理哪？

  connect:    在 signalMap 中注册回调
  emit:       遍历 signalMap，逐一调用回调
  connect_to: 在目标实体的 signalMap 注册 + 在本实体的 listensTo 记录
```
