# 04 · 沙盒环境与元表

> 100 个实体共享 1 个 Lua VM，怎么让它们的脚本互不干扰？

---

## 4.1 问题：为什么不能直接执行脚本？

### 如果 100 个脚本实体都在全局环境中运行：

```lua
-- entity_a.lua
x = 10
function update(dt)
    x = x + dt * 5
end

-- entity_b.lua
x = 100                    -- ← 覆盖了 entity_a 的 x！
function update(dt)        -- ← 覆盖了 entity_a 的 update！
    x = x - dt * 3
end
```

**所有变量和函数都在全局表 `_G` 中，必然互相覆盖。**

---

## 4.2 解决方案：每实体一个沙盒 table

```
                    全局 VM (lua_State)
                    ┌────────────────────────────────┐
                    │  _G (全局表)                    │
                    │  ├── print                      │
                    │  ├── math.sin                   │
                    │  └── ...                        │
                    │                                 │
                    │  注册表                          │
                    │  ├── envRef_42 ← 实体 42 的沙盒  │
                    │  │   ├── x = 10                 │
                    │  │   ├── update = function(dt)  │
                    │  │   ├── get_position = function │
                    │  │   └── ...                    │
                    │  │                              │
                    │  ├── envRef_99 ← 实体 99 的沙盒  │
                    │  │   ├── x = 100                │
                    │  │   ├── update = function(dt)  │
                    │  │   └── ...                    │
                    │  └── ...                        │
                    └────────────────────────────────┘
```

每个实体有**独立的 table** 作为运行环境，互不干扰。

---

## 4.3 元表（metatable）—— 让沙盒能访问全局函数

### 问题

如果实体 #42 的沙盒 table 里只有 `x` 和 `update`，那脚本怎么写 `print("hello")`？

```
沙盒 table:
  x = 10
  update = function(dt) ... end
  get_position = function() ... end  ← 注入的 API

脚本执行:
  print("hello")  ← print 在哪？
```

### 解法：元表 `__index`

```lua
-- Lua 查找变量的顺序:
-- 1. 先在当前 table 里找
-- 2. 找不到 → 看元表有没有 __index
-- 3. 如果 __index 是一个 table → 去那个 table 里找

-- 设置元表:
local mt = { __index = _G }   -- __index 指向全局表
setmetatable(sandbox, mt)

-- 效果:
-- sandbox.x         → 在 sandbox 里找到了 → 10
-- sandbox.print     → sandbox 里没有 → 去 _G 里找 → 找到了！
-- sandbox.math.sin  → sandbox 里没有 → 去 _G.math.sin → 找到了！
```

### C API 实现

```c
static bool initEntity(lua_State *L, const ScriptComponent &sc, int &outEnvRef) {
    // ① 创建沙盒 table
    lua_newtable(L);                    // 栈: [sandbox]

    // ② 创建元表
    lua_newtable(L);                    // 栈: [sandbox, mt]
    lua_getglobal(L, "_G");            // 栈: [sandbox, mt, _G]
    lua_setfield(L, -2, "__index");    // mt.__index = _G;  栈: [sandbox, mt]
    lua_setmetatable(L, -2);           // setmetatable(sandbox, mt); 栈: [sandbox]

    // ③ 注入 API 函数
    injectApi(L);                       // 给 sandbox 加 get_position 等方法

    // ④ 保存沙盒到注册表（防止 GC 回收）
    outEnvRef = luaL_ref(L, LUA_REGISTRYINDEX);

    // ⑤ 编译并执行脚本
    int funcRef;
    if (!compileAndLoad(L, sc, &funcRef)) return false;
    // ... 执行脚本，此时脚本的全局变量会被写入 sandbox table ...
}
```

## 4.4 脚本如何"看到"沙盒环境

### 关键技巧：`lua_setupvalue`

问题：编译好的脚本默认在 `_G` 环境中执行。怎么让它改用 sandbox table 作为环境？

Lua 5.4 的解法（本项目用的方式）：

```c
// 编译脚本 → 得到一个 function（closure）
// 每个 Lua 函数都有一个隐藏的第一个 upvalue：_ENV
// _ENV 决定函数在哪个环境中查找全局变量

lua_rawgeti(L, LUA_REGISTRYINDEX, funcRef);  // 取出编译好的函数
lua_rawgeti(L, LUA_REGISTRYINDEX, outEnvRef); // 取出沙盒 table
lua_setupvalue(L, -2, 1);  // ★ 把函数的 _ENV 设为沙盒 table
//                    ↑
//      第 1 个 upvalue 就是 _ENV

// 现在这个函数执行时，所有全局变量都去沙盒 table 里找！
lua_pcall(L, 0, 0, 0);  // 执行脚本
```

### 效果

```lua
-- scripts/demo.lua
x = 10                          -- 写入 sandbox.x，不是 _G.x！

function update(dt)
    print("update called")      -- sandbox 里没有 print → 元表 __index 指向 _G → 找到
    self:set_position(x, 0, 0)  -- self = sandbox table
end
```

执行后，沙盒 table 的内容：

```
sandbox table:
  x      = 10            ← 脚本里的 x = 10
  update = function(dt)  ← 脚本里的 function update
  get_position = ...     ← injectApi 注入的
  set_position = ...     ← injectApi 注入的
  ...
  __index → _G           ← 元表（访问 print、math 等全局函数）
```

## 4.5 完整的记忆模型

```
实体 #42 执行脚本时的变量查找顺序:

  self:set_position(0, 0, 0)
       │
       ▼
  ① sandbox table 里有 "set_position" 吗？
     → 有！是 injectApi 注入的 C 函数。直接调用。
  
  脚本里写 x = 10:
       │
       ▼
  ① 写入 sandbox.x（不是 _G.x）
     因为 _ENV 被设为 sandbox

  脚本里写 print("hello"):
       │
       ▼
  ① sandbox table 里有 "print" 吗？
     → 没有。
  ② sandbox 有元表吗？
     → 有。元表的 __index 是 _G。
  ③ _G 里有 "print" 吗？
     → 有！调用 _G.print。
```

---

## 4.6 沙盒隔离的边界

| 能共享的 | 被隔离的 |
|----------|----------|
| 全局函数（print、math.sin、string.sub...） | 脚本变量（x、y、自定义函数...） |
| 注入的 C API（get_position、emit...） | 生命周期函数（update、ready） |
| 信号系统（通过 SignalComponent，跨实体通信） | 每个实体有自己独立的 update/ready |

---

## 4.7 总结

```
沙盒三部曲:

  ① lua_newtable()                    → 创建独立 table
  ② { __index = _G } 做元表           → 能访问全局函数
  ③ lua_setupvalue 替换 _ENV           → 脚本变量隔离

效果:
  100 个实体共享 1 个 VM
  每个有独立命名空间
  print、math 等全局函数透明可用
  API 函数只能访问"当前实体"的数据（通过 __active_ctx）
```
