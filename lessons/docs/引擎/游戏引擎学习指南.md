## 一、游戏引擎是什么

### 1.1 一句话定义

> 游戏引擎 = 一个**循环** + 若干**子系统**的集合。每帧做同样的事：读输入 → 跑逻辑 → 画画面。

### 1.2 核心子系统

任何游戏引擎都有这些"标配模块"：

```
┌──────────────────────────────────────────────┐
│                  游戏引擎                      │
│                                              │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐        │
│  │ 渲染  │ │ 物理  │ │ 脚本  │ │ 动画  │  ...  │
│  │ 器    │ │ 引擎  │ │ 引擎  │ │ 系统  │        │
│  └──┬───┘ └──┬───┘ └──┬───┘ └──┬───┘        │
│     │        │        │        │             │
│     └────────┴────┬───┴────────┘             │
│                   ▼                          │
│            ┌─────────────┐                   │
│            │  ECS 世界    │ ← 所有数据在此     │
│            └─────────────┘                   │
└──────────────────────────────────────────────┘
```

## 二、项目全局架构

### 2.1 架构图

```
用户操作（编辑栏 / WASD + 右键）
        │
        ▼
┌─────────────────────────────────────────────────────┐
│                    MainWindow                        │
│                                                     │
│  ┌──────────┐  ┌────────────┐  ┌──────────────────┐ │
│  │EditorPanel│  │   Engine   │  │   RenderWidget   │ │
│  │  (Qt UI)  │  │ (ECS 核心) │  │  (OpenGL 视口)   │ │
│  │           │  │            │  │                  │ │
│  │ 实体列表   │  │ flecs::    │  │ paintGL 每帧:    │ │
│  │ 组件列表   │─▶│ world ◀───│─▶│ 多Pass绘制        │ │
│  │ 属性面板   │  │            │  │                  │ │
│  │           │  │ systems[]  │  │                  │ │
│  └──────────┘  └────────────┘  └──────────────────┘ │
│                                                     │

```

**核心原则**：数据总是从 ECS World 进出。编辑栏写 World，System 读 World 改 World，RenderWidget 读 World 画。

### 2.2 每帧执行顺序（完整 Phase 管线）

```
QTimer::timeout (每 16ms)
  │
  ├─ 1. Time::step(dt)               — 全局时钟（含死亡螺旋保护 dt>0.25 钳制）
  ├─ 2. Engine::runFrame(dt)         — 按 phase 升序执行所有 System
  │     ├─ CameraSystem (phase=50)   — 编辑器摄像机
  │     ├─ PhysicsSystem (phase=90)  — 物理模拟（固定步长 1/60s）
  │     ├─ ScriptSystem (phase=100)  — Lua 脚本
  │     ├─ RotationSystem (phase=100)
  │     ├─ TweenSystem (phase=105)   — 补间（脚本发起的一次性过渡）
  │     ├─ AnimFsmSystem (phase=108) — 动画状态机（参数驱动的切换判定）
  │     ├─ AnimationSystem (phase=110) — 动画采样（关键帧 + crossfade 混合）
  │     ├─ ParticleSystem (phase=110)  — 粒子发射/积分/回收
  │     ├─ AudioSystem (phase=120)     — 音频（仅 Play）
  │     └─ TransformSystem (phase=150) — 父子层级传播
  ├─ 3. Input::endFrame()            — 清理一次性事件
  └─ 4. RenderWidget::update()       — 触发 paintGL 渲染
```

## 三、ECS 架构详解

### 3.1 什么是 ECS

传统面向对象（GameObject 继承链）的问题：

```cpp
// 传统做法 —— "致命钻石"：
class Entity { /* 位置 */ };
class MovableEntity : public Entity { /* + 速度 */ };
class VisibleEntity : public Entity { /* + 渲染 */ };
class MovableVisibleEntity : public MovableEntity, public VisibleEntity { /* 菱形继承! */ };
```

ECS 的思路是**组合优于继承**：

```
Entity（实体）= 只是一个 ID，没有数据，没有方法
Component（组件）= 纯数据 struct
System（系统）= 遍历有某组件的实体，执行逻辑
```

### 3.2 Flecs 核心 API

本项目使用 [Flecs 4.1.6](https://github.com/SanderMertens/flecs)：

```cpp
flecs::world world;  // ECS 世界（所有数据在此）

// 注册组件类型
world.component<TransformComponent>();
world.component<MeshComponent>();

// 创建实体 + 添加组件
auto entity = world.entity();
entity.set<TransformComponent>({/* position, rotation, scale */});
entity.set<TagComponent>({"Player"});

// 系统遍历：只处理"同时有 Transform + RotateBehavior"的实体
world.each([](TransformComponent &tf, const RotateBehavior &rb) {
    tf.rotation.y += rb.speedY * dt;
});
```

### 3.3 本项目组件一览

| 组件 | 职责 | 关键字段 |
|------|------|---------|
| `TransformComponent` | 位置/旋转/缩放 + 世界矩阵 | position, rotation, scale, worldMatrix, visible |
| `MeshComponent` | 网格资源引用 | meshHandle, meshType |
| `MaterialComponent` | PBR 材质 | albedo, metallic, roughness, ao |
| `TagComponent` | 实体名称 | name[64] |
| `CameraComponent` | 摄像机 | position, fov, viewMatrix, isEditor, active |
| `RotateBehavior` | 自动旋转 | speedX, speedY, speedZ |
| `ScriptComponent` | Lua 脚本 | filePath, source, properties |
| `SignalComponent` | 信号系统 | signalMap, listensTo |
| `RigidbodyComponent` | 刚体类型/质量 | motionType, mass, friction, restitution |
| `BoxColliderComponent` | 碰撞盒 | halfExtents |
| `AnimationComponent` | 动画播放 + crossfade | animFile, current, playing, loop, time, prev |
| `HealthComponent` | 生命值 | hp, maxHp |
| `SpriteComponent` | 精灵帧动画 | folder, frame |
| `LightComponent` | 光源（方向/点/聚光） | type, direction, diffuse, intensity, range, spotAngle |
| `EnvironmentComponent` | 场景环境（对标 WorldEnvironment） | 天空色, exposure, vignette, fogColor, fogDensity |
| `ParticleComponent` | 粒子发射器 | rate, lifetime, direction, spread, gravity, color, additive |
| `AudioComponent` | 音源 | file, volume, loop, autoplay, spatial |

### 3.4 系统（System）设计

所有系统继承 `System` 基类：

```cpp
class System {
public:
    virtual int phase() const { return 0; }      // 执行顺序
    virtual int activeIn() const { return kAllStates; } // 编辑/运行模式
    virtual void update(flecs::world &world, float dt) = 0;
    virtual void shutdown() {}
};
```

**Phase 顺序的意义**：

```
Camera(50) → Physics(90) → Script(100) → Tween(105) → AnimFsm(108) → Animation/Particle(110) → Audio(120) → Transform(150) → Render
     ↑            ↑            ↑              ↑               ↑                  ↑                         ↑
  输入响应     物理模拟    脚本逻辑      补间过渡     动画状态机判定     动画采样/粒子模拟           层级传播（最后，确保本帧最终结果）
```

## 四、主循环与状态机

### 4.1 游戏循环

```cpp
// MainWindow 构造函数中：
m_timer = new QTimer(this);
connect(m_timer, &QTimer::timeout, this, [this]() {
    float rawDt = m_elapsed.restart() / 1000.f;  // 真实时间间隔
    Time::instance().step(rawDt);                  // 全局时钟
    m_engine->runFrame(time.delta);               // 驱动所有 System
    Input::instance().endFrame();                  // 清理一次性输入
    m_renderWidget->update();                      // 触发重绘
});
m_timer->start(16);  // 约 60 FPS
```

### 4.2 编辑/运行双模式

项目使用 [HFSM2](https://github.com/andrew-gresyk/HFSM2) 层次状态机：

```
EngineState::Edit  ──Tab/▶按钮──▶  EngineState::Play
       ◀─── Esc/■按钮 ────
```

关键设计点：

1. **System 按状态启停**：`activeIn()` 返回位掩码，Engine 自动处理
   - `PhysicsSystem` 只在 Play 运行
   - `ScriptSystem` 只在 Play 运行
   - `AudioSystem` 只在 Play 运行
   - `CameraSystem` / `ParticleSystem` 两个状态都运行

2. **场景快照**：进入 Play 前保存所有 Transform，退出后还原——对标 Godot 的"运行不污染编辑场景"

3. **回调解耦**：MainWindow 通过 `EngineContext` 注册 enter/exit 回调
   - ⚠ 重要教训：`ContextT<EngineContext&>` 必须是引用语义！（值语义会让 FSM 内部持有一份空回调的拷贝）

## 五、渲染管线

### 5.1 完整流程（多 Pass）

> 📖 完整的逐段走读（PBR/Cook-Torrance/阴影 PCF/粒子 billboard/后处理色调映射）见专题文档：[渲染系统实战](渲染系统实战.md)。

```
paintGL() 每帧执行：
  │
  ├─ 1. flushPendingDeletes()          — 清理待删 GPU 资源
  ├─ 2. Pass1 阴影：renderShadowPass()  — 方向光深度贴图(1024²) + 点光深度 cubemap
  ├─ 3. 绑 HDR 离屏 FBO(RGBA16F)         — 主场景画到浮点纹理
  ├─ 4. 选相机（编辑器优先）→ view/proj
  ├─ 5. drawSky → drawGizmo
  ├─ 6. 上传多光源(≤8) + 绑阴影贴图
  ├─ 7. Pass2 主场景：PBR 材质遍历实体
  ├─ 8. Pass3 粒子：GPU 实例化 billboard
  ├─ 9. Pass4 后处理：色调映射+暗角上屏
  └─ 10. drawCameraPreview — 选中相机小窗预览
```

### 5.2 Shader：PBR + 多光源 + 阴影

材质模型是 **PBR 金属度/粗糙度工作流**（Cook-Torrance BRDF），对标 Godot StandardMaterial3D：

```glsl
struct Material { vec3 albedo; float metallic; float roughness; float ao; };
// 逐光源累加：方向光有阴影 PCF（3×3 软化），点光有深度 cubemap 阴影
for (int i = 0; i < uLightCount; ++i)
    result += calcLight(uLights[i], norm, viewDir);
```

**阴影双系统**：方向光用正交投影单张深度图，点光用深度 cubemap（6 面渲染到 512² 立方体贴图，线性距离存储，方向采样精度更高）。

### 5.3 环境组件

`EnvironmentComponent` 把天空渐变色、曝光、暗角、距离雾变成"场景数据"——编辑器实时可调，改场景氛围不重编译。

### 5.4 相机预览

选中相机实体 → 右下角小窗用 viewport + scissor 重画场景（简化渲染：无阴影/后处理，纯相机视角预览），对标 Godot Camera3D preview。

## 六、脚本系统

### 6.1 整体架构

```
┌─────────────────────────────────────────┐
│              ScriptSystem                │
│                                         │
│  1 个 lua_State（Lua VM）               │
│  N 个沙盒 table（每个实体一个）          │
│                                         │
│  Lua 脚本生命周期：                      │
│    ready()  — 初始化时调用一次           │
│    update(dt) — 每帧调用                │
└─────────────────────────────────────────┘
```

### 6.2 沙盒隔离

每个实体的脚本运行在独立环境中。C++ 不拷贝 TransformComponent 数据进 Lua，而是通过 `LuaCtx` 结构体传指针——零拷贝上下文传递。

### 6.3 信号系统

对标 Godot 的 `signal.connect` / `signal.emit`，支持跨实体连接（`connect_to`）、异步延迟执行（work 线程 emit 入队 → 主线程消费）。信号通过多线程安全的队列传递（`g_signalQueue`），主线程每帧消费。

### 6.4 异步任务

`async(lua_code, callback)`：工作线程用独立 `lua_State` 执行，结果经队列回主线程调回调——对标 Godot 的 `await` / 线程 API。

## 七、物理引擎

### 7.1 Jolt Physics 集成

使用 [Jolt Physics](https://github.com/jrouwe/JoltPhysics)（工业级，Horizon Zero Dawn 同款）。

```
组件 → Jolt 世界映射：
  RigidbodyComponent  →  Jolt Body（Static / Kinematic / Dynamic）
  BoxColliderComponent →  Jolt BoxShape（halfExtent）
  TransformComponent  →  Jolt 位置/旋转
```

### 7.2 物理步进（固定步长 + 插值）

用**自己的累加器**跑固定步长 1/60s，含死亡螺旋保护（`dt=min(dt,0.25f)`）。物理插值（prevPos/currPos lerp）消除物理与渲染节拍不匹配导致的 60Hz 阶梯抖动。

- **只有 Dynamic 回写 Transform**；Kinematic/Static 由脚本 `physicsSetPosition` 等 API 驱动
- **质量必须显式设**：不设时 Jolt 按体积×密度(1000kg/m³) 算，冲量推不动
- **改速度前先唤醒**：睡眠刚体 `SetLinearVelocity` 不唤醒，落地后 WASD 失效

### 7.3 碰撞信号

Jolt 工作线程检测到碰撞 → `EcsContactListener::OnContactAdded` → 推入 `g_signalQueue`（双向，两个实体都能收到 `"collision"` 信号）→ ScriptSystem 消费 → Lua 回调。

## 八、动画系统

### 8.1 对标 Godot AnimationPlayer

```
Godot AnimationPlayer 节点  →  AnimationComponent（播放状态）
Godot Animation 资源(.tres) →  .anim 文件（JSON，含多个命名 clip）
Godot play("walk")          →  Lua: anim_play("walk")
```

### 8.2 .anim 文件格式

```json
{
  "clips": {
    "spin": {
      "duration": 2.0,
      "tracks": [
        { "target": "TransformComponent", "field": "rotation",
          "keys": [{"t":0,"v":[0,0,0]}, {"t":2,"v":[0,360,0],"easing":6}] }
      ]
    }
  }
}
```

轨道不限于 Transform：target/field 是反射路径（如 `MaterialComponent/diffuse`），任何 `REFLECT` 注册的字段都能动画。

### 8.3 事件轨道（Method Track）

动画时间线上的事件点 → AnimationSystem 跨帧检测（离散帧率下不能用 `==` 判时刻，必须区间跨越）→ 推入信号队列 → 脚本 `connect` 接收。

### 8.4 crossfade 混合

`anim_crossfade("run", 0.2)`：在两个 clip 间按权重 lerp，过渡完成后自动回到单动画路径。动画状态机（第十章）使用了同一个 crossfade 机制。

## 九、补间系统（Tween）

对标 Godot Tween / `create_tween()`。解决"脚本一行平滑动画"的需求——与 AnimationComponent 的分工：**动画 = 设计期资产（.anim 文件、循环播放），Tween = 运行期一次性过渡（播完即弃）**。

### 用法

```lua
tween(id, "position", x, y, z, 0.5, "ease_out")           -- 门滑开
tween(id, "rotation", 0, 180, 0, 1.0, "bounce")           -- 招牌翻转
tween(id, "scale", 2, 2, 2, 0.3, "elastic", "grow_done")  -- 完成发信号
```

### 实现

TweenSystem（phase=105，脚本之后）维护活动补间列表（System 内部私有）。同实体同属性的新 tween 顶掉旧的（Godot 行为：后发优先）。退出 Play 时 `clearAll()` 清空全部。

## 十、动画状态机

对标 Godot AnimationTree / StateMachine。**把"什么时候切哪个动画"变成声明式规则**，脚本只喂参数，切换自动发生（带 crossfade）。

### 用法

```lua
-- ready() 里声明状态图（一次）：
anim_fsm_add(id, "idle", "walk", "speed", ">", 0.5, 0.2)
anim_fsm_add(id, "walk", "idle", "speed", "<", 0.1, 0.2)
anim_fsm_add(id, "walk", "run",  "speed", ">", 4.0, 0.15)
anim_fsm_start(id, "idle")

-- update() 里只更新参数：
anim_fsm_param(id, "speed", 当前速度)  -- 切换自动发生
```

**约定**：状态名 = 动画 clip 名，切换走 `AnimationComponent` 的 crossfade。

### 实现

`AnimFsmSystem`（phase=108，脚本之后、动画采样之前）维护实体的状态机数据（运行时 `map` 结构，存在 System 内部）。脚本传参 → 每帧检查转移条件（`fParam op threshold` 成立 → 触发 crossfade）。退 Play 时 `clearAll()` 清空。

## 十一、粒子系统

对标 Godot CPUParticles3D，**CPU 模拟 + GPU 实例化**。

### 分工

- **ParticleSystem（phase=110）**：纯 CPU 逻辑（发射/积分/回收），可无 GL 单测
- **RenderWidget::drawParticles**：粒子池打包 instance buffer → `glDrawArraysInstanced` 一次画全部

### 细节

- 粒子在**世界空间**模拟（发射后不跟随发射器 → 火把挥舞留拖尾）
- billboard 在 vertex shader 用相机右/上轴展开 quad
- `additive=1` 用加法混合（火/光效发亮叠加），`=0` 用普通 alpha（烟/尘）
- 排在不透明物体之后、后处理之前，且在 HDR 纹理内 `intensity>1` 经色调映射有辉光感

## 十三、寻路系统（A*）

对标 Godot NavigationServer，**方块世界的简化版**：64×64 网格（1m/格），A* 寻路（8 方向）+ 视线平滑拉直锯齿路径。

### 三步用法

```lua
-- ① 烘焙：把静态碰撞体占地格标记为障碍（进关卡时一次）
nav_bake()

-- ② 寻路：返回路点序列（世界坐标格中心）
local path = nav_find_path(fromX, fromZ, toX, toZ)

-- ③ 跟随：每帧拿下一个路点，朝它移动
local x, z = nav_next_point(path, curX, curZ)
```

### 算法细节

- **A***：小顶堆 open 列表 + 对角距离启发；对角移动要求两侧直格都通（防"穿墙角"）
- **视线平滑**（string pulling 简版）：从当前点尽量直连最远可见格，经过的格子 DDA 步进采样
- 纯逻辑无依赖（不认 flecs/GL）→ 可完整单元测试

## 十四、模型导入（OBJ）

自写 Wavefront OBJ 解析器，学习目的。

**支持**：顶点位置(v)、纹理坐标(vt)、法线(vn)、面(f)四种格式（v/vt/v//vn/v/vt/vn）+ 四边形/多边形自动扇形三角化

**不支持**：材质(.mtl)、组、平滑组——颜色走引擎 `MaterialComponent`（PBR）

**输出**：展开的非索引三角形顶点数组，布局与 `MeshFactory::createCube` 完全一致 → 复用 `default.vert/frag` 全套光照/阴影/PBR。无法线的 OBJ 自动算面法线（叉积，平面着色）。

## 十六、资源管理

### 16.1 句柄模式（对标 Unreal/Unity）

```
实体A ─┐
实体B ─┼─ meshHandle=1 ──▶ ["cube" refCount=3, VAO=5]
实体C ─┘                    ↑ 100 个立方体只占 1 份显存
```

### 16.2 延迟 GPU 操作 —— 解耦关键

```
acquireMesh()  = 纯登记（不碰 GL！任何时机安全）
get(handle)    = 首次访问才创建 GPU 数据（在 paintGL，天然有上下文）
releaseMesh()  = 引用归零只挂"待删列表"
flushPendingDeletes() = 每帧渲染前统一 glDelete
```

解决 GL 操作必须在上下文才能调用的时序难题。配合 `OnRemove` observer 自动释放——调用方不需要"记得释放"。

## 十八、射线拾取

### 18.1 核心思路：渲染管线倒着走

```
渲染（正向）：世界坐标 → view → proj → NDC → 屏幕像素
拾取（逆向）：屏幕像素 → NDC → inverse(proj*view) → 世界射线
```

### 18.2 OBB 拾取技巧

旋转/缩放过的立方体不用在世界空间算斜包围盒——把射线用 `inverse(worldMatrix)` 变换到实体局部空间，与"单位 AABB（±0.5）"求交。**方向用 w=0！**

### 18.3 解耦设计

视口不认识编辑器面板——只发 `entityPicked(id)` 信号，MainWindow 负责接线。

## 十九、缓动算法库

### 19.1 Robert Penner 缓动方程

```cpp
float ease(EasingType type, float t);  // t∈[0,1] → 缓动进度

// 13 种内置算法 + 自定义贝塞尔：
kLinear          — t
kEaseInQuad      — t²
kEaseOutBounce   — 落地弹跳（球落地）
kEaseOutElastic  — 弹簧回弹（UI 弹出）
kCustomBezier    — cubic-bezier(x1,y1,x2,y2) 四参数曲线
```

### 19.2 策略模式设计

纯数学函数，零外部依赖，任何模块都能用：动画关键帧插值、相机平滑跟随、UI 过渡、补间（tween）。**扩展**：加新算法只需枚举加一项 + switch 加一个 case → 开闭原则。

## 二十、多线程系统

### 20.1 工作线程池

```cpp
class JobSystem {
    // 4 个工作线程（cv + 原子计数 pending），从队列取任务执行
    void submit(std::function<void()> job);
};
```

### 20.2 信号的多线程安全

C++ 工作线程（物理碰撞、异步任务）直接推入信号队列（持锁），主线程每帧消费。**关键教训**：信号走队列而非直接调 Lua——① Lua VM 非线程安全；② 避免回调中修改 ECS 致迭代器失效。

### 20.3 自检/统计框架（TestFramework）

运行时诊断接口，供 AI Agent/脚本排障（对标 Godot 的 Remote Debug）：

```cpp
// ① 断言宏：失败记录到日志 + 计数（仅测试构建编译）
ET_CHECK(entity.is_alive(), "entity must be alive");

// ② 帧统计（RenderWidget 每帧自动收集）
EngineTest::stats().drawCalls;   // DrawCall 次数
EngineTest::stats().uniformSets; // uniform 更新次数
EngineTest::statsReport();       // 多行文本快照
```

```lua
-- ③ Lua API：脚本里一键输出状态快照（排障神器）
print(engine_stats())       -- DrawCall/uniform/实体数/断言结果
print(engine_self_check())  -- 自检项 PASS/FAIL 摘要
```

**零开销开关**：CMake `option(ENABLE_ENGINE_TESTING)`——关闭（默认）时所有宏展开为空，Release 构建零运行时成本；三个测试目标强制开启以验证完整逻辑。
