# 04 · 转换、守卫与动作

> changeTo 的完整用法、条件转换（守卫）、事件驱动转换、update 驱动。

---

## 4.1 转换方式汇总

| 方法 | 调用位置 | 生效时机 |
|------|---------|---------|
| `control.changeTo<S>()` | 状态回调内 | 下次 `machine.update()` |
| `control.immediateChangeTo<S>()` | 状态回调内 | 立即 |
| `machine.changeTo<S>()` | 外部代码 | 下次 `machine.update()` |
| `machine.immediateChangeTo<S>()` | 外部代码 | 立即 |

## 4.2 条件转换（守卫模式）

在 `update` 中检查条件，满足则转换：

```cpp
struct Patrol : FSM::State {
    void update(Control &control) {
        auto &ctx = control.context();

        // 守卫：发现玩家 → 切换到追击
        if (ctx.playerDetected)
            control.changeTo<Chase>();

        // 守卫：血量低 → 切换到逃跑
        if (ctx.hp < 20)
            control.changeTo<Flee>();
    }
};

struct Chase : FSM::State {
    void update(Control &control) {
        auto &ctx = control.context();

        // 守卫：距离足够近 → 切换到攻击
        if (ctx.distanceToPlayer < 2.0f)
            control.changeTo<Attack>();

        // 守卫：丢失目标 → 回到巡逻
        if (!ctx.playerDetected)
            control.changeTo<Patrol>();
    }
};
```

**模式**：`update` = 每帧检查守卫条件 → 满足则 `changeTo`。

## 4.3 enter 中触发转换（链式）

```cpp
struct Loading : FSM::State {
    void enter(Control &control) {
        // 加载资源...
        bool success = loadAssets();

        if (success)
            control.changeTo<Playing>();   // 加载成功 → 进入游戏
        else
            control.changeTo<Error>();     // 加载失败 → 错误界面
    }
};
```

## 4.4 事件驱动转换（react）

```cpp
// 定义事件
struct PauseEvent {};
struct ResumeEvent {};
struct QuitEvent {};

struct Playing : FSM::State {
    // react 在 machine.react(event) 时触发
    void react(const PauseEvent &, Control &control) {
        control.changeTo<Paused>();
    }

    void react(const QuitEvent &, Control &control) {
        control.changeTo<Menu>();
    }
};

struct Paused : FSM::State {
    void react(const ResumeEvent &, Control &control) {
        control.changeTo<Playing>();
    }

    void react(const QuitEvent &, Control &control) {
        control.changeTo<Menu>();
    }
};

// 外部触发事件
machine.react(PauseEvent{});   // Playing → Paused
machine.react(ResumeEvent{});  // Paused → Playing
machine.react(QuitEvent{});    // → Menu
```

**与 update 守卫的区别**：

- 守卫：每帧轮询条件（适合持续检测，如距离、血量）
- 事件：外部主动触发（适合离散事件，如按键、网络消息）

## 4.5 update 驱动模式

```cpp
int main() {
    FSM::Instance machine;

    // 游戏主循环
    while (running) {
        float dt = getDeltaTime();

        // 1. 处理输入 → 可能触发事件
        if (keyPressed(KEY_ESCAPE))
            machine.react(PauseEvent{});

        // 2. 推进状态机（触发 update + 执行待处理的 changeTo）
        machine.update();

        // 3. 渲染当前状态
        render();
    }
}
```

**执行顺序**：

1. `react(event)` → 触发当前状态的 `react` 回调 → 可能标记 `changeTo`
2. `update()` → 执行待处理的转换（exit 旧状态 → enter 新状态）→ 调用新状态的 `update`

## 4.6 转换时的回调顺序

从 StateA 切换到 StateB 时：

```
1. StateA::exit(control)      ← 旧状态退出
2. StateB::enter(control)     ← 新状态进入
3. StateB::update(control)    ← 新状态首帧（如果是 machine.update() 触发）
```

如果是层次状态机（A 和 B 有共同父状态 P）：

```
1. A::exit                    ← 只退到共同父（P 不退出）
2. B::enter                   ← 进入新子状态
```

如果 A 和 B 没有共同父：

```
1. A::exit
2. ParentOfA::exit            ← 父也退出
3. ParentOfB::enter           ← 新父进入
4. B::enter
```

## 4.7 防止重复转换

```cpp
struct Playing : FSM::State {
    void update(Control &control) {
        // ❌ 每帧都调 changeTo（即使已经在目标状态）
        if (someCondition)
            control.changeTo<Paused>();  // 如果已经 Paused 了？

        // ✅ 先检查当前状态
        if (someCondition && !control.isActive<Paused>())
            control.changeTo<Paused>();
    }
};
```
