# 02 · 层次状态机

> 父/子状态嵌套、Composite 与 Peer 的区别、进入/退出传播规则。

---

## 2.1 为什么需要层次

扁平状态机（所有状态平级）在状态多时转换爆炸：

```
// 扁平：5 个状态 × 4 个转换 = 20 条边
Menu ↔ Playing ↔ Paused ↔ Loading ↔ GameOver
```

层次状态机把相关状态**分组到父状态下**：

```
Root
├── Menu
└── InGame (父)
    ├── Playing (子)
    ├── Paused (子)
    └── Loading (子)
```

好处：

- 从 Playing 切到 Paused，**不需要退出 InGame**（父状态保持）
- InGame 的 enter/exit 只在"进入游戏/退出游戏"时触发一次
- 减少转换边数，逻辑更清晰

## 2.2 Composite（组合状态）

用 `Composite` 定义父状态（包含子状态）：

```cpp
using M = hfsm2::MachineT<hfsm2::Config>;
using FSM = M::PeerRoot<
    struct Menu,
    struct InGame    // 前向声明
>;

// InGame 是一个 Composite，包含子状态
struct InGame : FSM::State {
    using Composite = M::Composite<
        struct Playing,
        struct Paused
    >;

    void enter(Control &control) {
        std::cout << "进入游戏模式\n";
    }
    void exit(Control &control) {
        std::cout << "退出游戏模式\n";
    }
};

// 子状态定义
struct Playing : InGame::Composite::State {
    void enter(Control &control) { std::cout << "  开始玩\n"; }
    void exit(Control &control) { std::cout << "  停止玩\n"; }
};

struct Paused : InGame::Composite::State {
    void enter(Control &control) { std::cout << "  暂停中\n"; }
    void exit(Control &control) { std::cout << "  取消暂停\n"; }
};

struct Menu : FSM::State {
    void enter(Control &control) { std::cout << "主菜单\n"; }
};
```

## 2.3 进入/退出传播

```cpp
FSM::Instance machine;
// 初始状态：Menu（PeerRoot 列表第一个）

machine.changeTo<Playing>();
machine.update();
```

**输出**：

```
主菜单          ← Menu::exit（离开菜单）
进入游戏模式    ← InGame::enter（父状态进入）
  开始玩        ← Playing::enter（子状态进入）
```

从 Playing 切到 Paused：

```cpp
machine.changeTo<Paused>();
machine.update();
```

**输出**：

```
  停止玩        ← Playing::exit（旧子状态退出）
  暂停中        ← Paused::enter（新子状态进入）
```

**注意**：InGame 的 enter/exit **没有再次触发**——因为父状态没变，只是子状态在切换。

从 Paused 切回 Menu：

```cpp
machine.changeTo<Menu>();
machine.update();
```

**输出**：

```
  取消暂停      ← Paused::exit（子状态退出）
退出游戏模式    ← InGame::exit（父状态退出）
主菜单          ← Menu::enter（新状态进入）
```

## 2.4 Peer vs Composite

| 容器类型 | 行为 | 适用场景 |
|---------|------|---------|
| `PeerRoot<A, B, C>` | A/B/C 平级，同时只有一个活跃 | 互斥状态（菜单/游戏/设置） |
| `Composite<A, B>` | A/B 是子状态，父状态包裹它们 | 分组（游戏内的 玩/暂停） |
| `Orthogonal<A, B>` | A/B 同时活跃（并行区域） | 独立子系统（移动 + 射击同时） |

## 2.5 多层嵌套

```cpp
struct Root : FSM::State {
    using Composite = M::Composite<
        struct Menu,
        struct Game
    >;
};

struct Game : Root::Composite::State {
    using Composite = M::Composite<
        struct Playing,
        struct Paused,
        struct Cutscene
    >;
};

// 三层：Root → Game → Playing
```

进入 Playing 时：`Root::enter → Game::enter → Playing::enter`（从外到内）
退出到 Menu 时：`Playing::exit → Game::exit → Menu::enter`（从内到外）

---

## 2.6 初始子状态

Composite 的**第一个子状态**是默认初始状态：

```cpp
struct InGame : FSM::State {
    using Composite = M::Composite<
        struct Playing,   // ← 第一个 = 进入 InGame 时默认激活 Playing
        struct Paused
    >;
};
```

进入 InGame 时，如果没有指定具体子状态，自动进入 Playing。
