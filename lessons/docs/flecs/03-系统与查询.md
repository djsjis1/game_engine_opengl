# 03 · 系统与查询

> system 创建、query 过滤、可选组件、排除组件、性能要点。

---

## 3.1 系统（System）

系统 = 查询 + 逻辑。每帧 `ecs.progress()` 时自动执行。

```cpp
// 最简系统：遍历有 Position + Velocity 的实体
ecs.system<Position, Velocity>()
    .each([](Position &p, Velocity &v) {
        p.x += v.dx;
        p.y += v.dy;
    });

// 带实体参数
ecs.system<Position, Health>()
    .each([](flecs::entity e, Position &p, Health &h) {
        if (h.hp <= 0) e.destruct();  // 血量归零 → 销毁
    });

// 带 dt（帧间隔）
ecs.system<Position, Velocity>()
    .each([](flecs::iter &it, Position &p, Velocity &v) {
        float dt = it.delta_time();
        p.x += v.dx * dt;
    });
```

---

## 3.2 查询（Query）

Query 是"可复用的过滤条件"，不绑定执行逻辑：

```cpp
// 创建查询
flecs::query<Position, Velocity> q = ecs.query<Position, Velocity>();

// 手动遍历（不在系统里也能用）
q.each([](Position &p, Velocity &v) {
    p.x += v.dx;
});

// 带过滤的查询
flecs::query<Position> q2 = ecs.query_builder<Position>()
    .with<Enemy>()          // 必须有 Enemy 标记
    .without<Invisible>()   // 必须没有 Invisible
    .build();
```

---

## 3.3 过滤条件

```cpp
ecs.query_builder<Position>()
    .with<Velocity>()       // AND：必须也有 Velocity
    .with<Enemy>()          // AND：必须也有 Enemy
    .without<Dead>()        // NOT：不能有 Dead
    .optional<Shield>()     // OPTIONAL：有则传入，无则 nullptr
    .build();
```

### 可选组件

```cpp
ecs.system<Position>()
    .each([](flecs::entity e, Position &p) {
        // 手动检查可选组件
        const Shield *s = e.get<Shield>();
        if (s) {
            // 有护盾：减伤
        }
    });
```

## 3.4 world.each（快捷遍历）

不创建系统，直接遍历（适合一次性操作）：

```cpp
// 遍历所有有 Position 的实体
ecs.each([](flecs::entity e, Position &p) {
    p.x = 0;  // 全部归零
});

// 多组件
ecs.each<Position, Velocity>([](Position &p, Velocity &v) {
    p.x += v.dx;
});
```

**与 system 的区别**：`each` 是一次性执行；`system` 注册后每次 `progress()` 都执行。

---

## 3.5 系统执行顺序

Flecs 默认按创建顺序执行。可以用 Pipeline + Phase 控制：

```cpp
// 使用内置 Phase 排序
ecs.system<Position, Velocity>()
    .kind(flecs::OnUpdate)    // 在 OnUpdate 阶段执行
    .each([](Position &p, Velocity &v) { ... });

ecs.system<Position>()
    .kind(flecs::PostUpdate)  // 在 OnUpdate 之后执行
    .each([](Position &p) { ... });
```

内置 Phase 顺序：`OnLoad → PostLoad → PreUpdate → OnUpdate → OnValidate → PostUpdate → PreStore → OnStore`

---

## 3.6 禁用/启用系统

```cpp
flecs::entity sys = ecs.system<Position>()
    .each([](Position &p) { ... });

sys.disable();   // 暂停（progress 时跳过）
sys.enable();    // 恢复
```

## 3.7 性能要点

| 要点 | 说明 |
|------|------|
| 组件连续存储 | 同一 archetype 的实体组件在内存中紧挨，遍历缓存友好 |
| 查询缓存 | Flecs 缓存查询匹配的 archetype 列表，不每次重新搜索 |
| 避免频繁增删组件 | 增删组件会导致实体在 archetype 间迁移（开销大） |
| 遍历时不要 destruct | 遍历中销毁实体会导致迭代器失效，用标记 + 后处理 |
| 只查询需要的组件 | `each<Position>` 比 `each<Position, Velocity, Health, ...>` 快 |

### 遍历中安全删除的模式

```cpp
// ❌ 错误：遍历中直接 destruct
ecs.each<Health>([](flecs::entity e, Health &h) {
    if (h.hp <= 0) e.destruct();  // 危险！可能使迭代器失效
});

// ✅ 正确：先收集，后删除
std::vector<flecs::entity> toDelete;
ecs.each<Health>([&](flecs::entity e, Health &h) {
    if (h.hp <= 0) toDelete.push_back(e);
});
for (auto &e : toDelete) e.destruct();
```

## 3.8 C API 回退（MSVC 模板 bug 时的替代）

某些情况下 C++ API 的 `e.get<T>()` 在 MSVC 有模板推导问题，可用 C API：

```cpp
// C++ API（正常情况用这个）
const Position *p = e.get<Position>();

// C API 回退（模板出问题时）
const Position *p = static_cast<const Position *>(
    ecs_get_id(ecs, e.id(), ecs.component<Position>().id()));
```
