## 4. 命名规范（C++ / Qt 风格）

- **变量名**：小驼峰 `camelCase`
  - 示例：`shaderProgram`, `vertexArrayObject`
- **成员变量**：以 `m_` 前缀 + 小驼峰
  - 示例：`m_windowWidth`, `m_projectionMatrix`
- **函数/方法名**：动词开头，小驼峰，清晰描述功能
  - 示例：`initializeGL()`, `loadShader()`, `updateUniforms()`
- **类名**：大驼峰 `PascalCase`
  - 示例：`OpenGLWidget`, `ShaderProgram`
- **常量/宏**：全大写 + 下划线
  - 示例：`MAX_VERTEX_COUNT`, `DEFAULT_FOV`
- **文件名**：小写 + 下划线
  - 示例：`opengl_widget.cpp`, `shader_program.h`
- **GLSL 文件**：与对应 C++ 文件风格一致
  - 示例：`triangle.vert`, `lighting.frag`
- 命名应语义化，避免缩写（如用 `vertexCount` 而非 `vc`）

## 5. 编码规范

- 代码必须有注释，尤其是：
  - OpenGL API 调用序列的目的
  - 复杂的矩阵变换、光照计算
  - Shader 中各 uniform 的用途
- 保持代码风格统一，使用 4 空格缩进
- 对外接口、公共方法必须有文档说明
- OpenGL 资源管理（VBO/VAO/Shader/Texture）必须配对创建和释放
- Shader 编译错误必须打印日志并给出明确提示

## 6. AI 执行策略

- 每次执行前，检查 `docs/` 是否有相关文档可参考
- 代码生成或修改时，自动检查命名规范是否符合第 4 条
- 涉及新课时（lessonXX），参照已有课时的目录结构和代码组织方式
- 修改 shader 文件时，同步检查对应的 C++ 代码是否需要调整
- 输出结果附带关键代码的简要说明
